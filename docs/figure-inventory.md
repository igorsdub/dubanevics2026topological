# Figure inventory

The current figures, tables and exploratory stages of the repository, one section per family. Stable ids below are repository identifiers, independent of manuscript numbering; the manuscript map is `config/manuscript.toml` and `naming.py` copies renders to `output/figures/<section>/fig<number>_<desc>.png` (tables `tab<number>_<desc>`). Settings: scientific ones in `config/analysis.toml`, presentation ones in `config/figures.toml` (`[figures.<id>]`, shared keys in `[rendering]`). The registry is `FIGURE_SPECS` in `src/dubanevics2026topological/figures/registry.py`. Terminology is in `GLOSSARY.md`; the design notes are the other documents in `docs/`.

## Output conventions

- Shelf files live under `output/figures/canonical/<figure_id>[__params].png`. Every render route (`build figures` and the article batch) draws each figure twice: without its figure-level heading to `canonical/`, and the titled twin (the chart with the heading its builder defines) to `canonical/titled/`, same file name; `build figures --no-titled-twins` writes the untitled render only. Panel and row titles (sequence counts, thresholds, row names) are content and stay in both; `figures/_title_flag.without_headings` is the one place that drops the root heading (axis titles, legends, colour-bar titles and bottom notes stay). A figures-job fetch brings `canonical/titled/` back with `canonical/`.
- PNG is 300 dpi; SVG is produced only by `just figures-svg`. The live hash list is `output/figures/manifest.csv`, written by `just name-outputs`. `git ls-files output/figures` lists only the canonical PNGs the manuscript uses (`config/manuscript.toml`); other renders, titled twins and sidecars are local.
- "Default" means the id is in the selection `build figures` renders with no `--figure`. Every figure a `config/manuscript.toml` source resolves to is default (a test keeps that true), so `just figures` renders the whole manuscript. Opt-in ids render with `uv run python -m dubanevics2026topological.build figures --figure <id>`, all of them with `just figures-exploratory` (`build figures --opt-in --keep-going`; each one lands in `output/figures/exploratory/`). The bootstrap ids read the bootstrap checkpoint (never recomputed by the render), which the loader restores from `data/processed/bootstrap/<state>/checkpoint`; `just figures` without `--figure` renders every default figure from `data/processed/`.
- Figures with notebooks are linked from their configuration entries; a notebook never calls `build_figure`.
- Panel sizes are shared: `tree_width` x `tree_height` (420 x 250) and `persistence_width` x `persistence_height` (250 x 250) in `[rendering]`; a figure's `tree` or `persistence` table sets them only to override. The intended exceptions are the 520 x 250 trees of `tree_comparison` and the 520 px tree of the codon-entropy figure. Baseline linked panels target 180 mm at 96 dpi.
- Outside the tree-histogram family, scalar axes round observed bounds outward to 0.1, tick at the rounded minimum, zero and rounded maximum, and add 5% of the rounded span on each side. The tree-histogram family and the Papkou tree comparison use the configured fitness domain directly (default [-1.2, 1.4]), 200 observed-range bins, and horizontal 110 px count colour bars inside the tree panels.

## Shared encodings

**Colour semantics** follow ADR 0012, which amends ADR 0010 and ADR 0009. Red is the wild type only: a solid red star (`#d62728`) on trees, never translucent. A stop codon is dark crimson (`#a50f15`), a cross on trees. Synonymous leaves are teal on the combined encoding (below) and green (`#1b9e77`) on the two-row annotation figures. Peaks are mid-grey (`#737373`) and always filled; black (`#111111`) is emphasis only (the absorbed peaks of the bootstrap figures); elder-protected is orange (`#ff7f0e`). No marker is hollow (GLOSSARY, Figure marker rules); a second state takes a second colour. The palette binds annotations, not figures: one colour per annotation wherever it appears. The persistence band is a translucent grey trapezoid clipped to the drawn diagonal's extent with no edge line (`band_color`, `band_opacity`); the full-graph noise band is a square with the same fill.

**Persistence diagrams** draw peaks only (no valley is drawn on the two-row and bootstrap figures; the full-graph figures draw valleys as described in that family). Shape means critical-point type and colour means annotation. Count opacity runs from `rendering.count_alpha_min` (0.3 at count one) to 1.0 at the largest count. The diagram key (`persistence_legend` in `figures/_charts.py`) sits inside the diagram, bottom right, one entry per line.

**Stop-codon marker rule.** On every merge-tree panel and slide the crimson cross sits on a node whose own sequence contains a stop codon and whose kind is in `rendering.stop_codon_tree_node_kinds` (default peaks and valleys, not saddles; `stop_codon_nodes` in `figures/_charts.py`). Persistence diagrams mark stop-codon peak births only. Tree and diagram keys read "Stop codon containing peaks" (`STOP_CODON_LEGEND_LABEL`); the diagram key's combined entry reads "≥1 stop codon" (`DIAGRAM_STOP_LABEL`). The tree cross is as large as the diagram triangles of the same figure (`rendering.stop_codon_tree_size` 70) with stroke `stop_codon_stroke_width` and opacity `stop_codon_tree_opacity`.

**Combined stop-and-synonymous encoding** (`full_tree_persistence`, its vertical variant, `tree_persistence_combined`, `bootstrap_band_combined`, `*_combined` comparisons). A synonymous leaf branch is teal on the tree, darker the more vertices it holds (`branch_count_teal`, `synonymous_teal_light` to `synonymous_teal_dark`, the same log scale as the grey count ramp). On a diagram a peak is a grey or teal `▲` and a valley a grey or teal `▼`, each with the branch-count fade; a stop codon is the tree's red `×` (`stop_cross_layer`) drawn on top, so a point that is both is a teal marker with a red `×`. The key reads `▲ peak`, `▼ valley` (full graph only), `● synonymous` and `× ≥1 stop codon`. A valley is synonymous when it has the amino acids of the join saddle it dies at (`synonymous_valley_sequences`). One marker size and one cross style apply: triangles and crosses use `rendering.stop_codon_tree_size` (`tree_marker_size`), the diagram cross takes the tree's stroke width and opacity.

**Branch order.** Every tree figure uses one child order, `subtree_extremum`: at each fork the child whose whole subtree reaches the highest peak goes first, so the highest peak, on the KEM ridge that holds the wild type, is the leftmost leaf (ADR 0011). Trees this repository lays out (`build_manifold_graph_tree`, every band-smoothed tree) take `horizontal_layout` from `tree_horizontal_layout()` (`figures/_layout_config.py`), which reads the one `[rendering] tree_horizontal_layout` key. Papkou2023 backbone trees (nominal Full, Published and Candidate, and row 1 of `candidate_tree_bootstrap_biology`) come from the article's own `papkou2023` package (`src/dubanevics2026topological/papkou2023/analysis.py`), which sets `subtree_extremum` itself, so the key does not reach them. Branch order is presentation only.

**Branch count colour.** Branch vertex count is black (`count_color`) whose opacity grows with the count on a log scale from `count_alpha_min` (0.3) at count 1 to `count_alpha_max` (1.0) at the figure tree's maximum, so count 1 has no swatch of its own (`figures/_branch_count_style.py`). Colour bars are horizontal, inside the tree panel (`colorbar_x_fraction` 0.9, ticks from `count_legend_ticks`; `overlay_count_colorbar`).

**Branch count labels.** The band-smoothed trees write each terminal branch of at most `branch_count_label_max` (9) sequences with its post-absorption vertex count as peak-grey text (`#737373`, body font minus `branch_count_label_font_reduction` 2 points, thousands separated, no amino-acid name; `figures/_count_labels.py`). `branch_count_label_mode` is `"tips"` (default; `"all"` also exists), `branch_count_label_collision` is `"nudge"` (default) or `"rotate"`. Labels are laid out in panel pixels (`figures/_label_layout.py`, pure geometry) clear of stop crosses, the star and its label, the colour bar, branches and each other; a label moved off its branch carries a thin peak-grey leader line. `"rotate"` turns labels a quarter turn; `just figures-rotated` (`--label-collision rotate`) renders it as `<figure_id>_rotated.png` without touching the canonical PNG. The two main ridges of the codon-entropy figure keep their own ridge count labels.

**Tree layer order.** Every tree panel stacks its layers bottom to top: underlays (the functional-threshold rule of `tree_comparison`), branches and branch overlays (highlighted or absorbed branches), count labels, stop-codon crosses, any inset key, then the wild-type star and its label. `compose_tree_layers` in `figures/_charts.py` owns the order and takes each layer by role; `tree_chart`, the biology rows and the codon-entropy trees stack through it.

**Axis titles.** Tree-persistence rows use one shared y axis titled `Fitness (at birth, WT = 0)` and the persistence x axis `Fitness at death`. `graph_tree_persistence` titles its axes `Fitness`, `Fitness at death` and `Fitness at birth`. Biological row headings name the observed count and category (stop-codon containing peaks, synonymous leaves). Each tree shows the red WT star and its left-side label.

**Functional threshold marking.** A tree figure draws only the functional threshold its panel uses, as a dashed rule (`functional_threshold_layers` in `figures/_charts.py`, `threshold_dash` `[5, 4]`; the median is dotted, `median_dash` `[1, 3]`). The value is named on the fitness axis as an extra tick with three decimals and in the subtitle `Functional threshold = <value>` (`functional_threshold_text`). A graph without a threshold (the Full graph) draws no rule. `tree_comparison` (the rule also crosses each row's histogram), the `tree_comparison_*_main` views, `reflected_fdr_trees` and `peak_uncertainty` follow this; the two study figures state the threshold in the subtitle only. The Candidate functional threshold is declared in `config/analysis.toml` (`[clamped] candidate_functional_threshold`) as the `fdr_fixed_cutoff` rule with the `median_reflected` cutoff, Benjamini–Yekutieli at nominal q = 0.05, read from the reviewed clean classification snapshot; its value is the Topographer threshold `m + (m - g)` = -0.253159. The Published landscape keeps its separately declared threshold (-0.507774). The `mixture_quantile` rule (ADR 2026-10-24) remains available as the variant `config/variants/mixture_quantile.toml`. The Topographer value is also the upper edge of the topological noise band. Config keys that spell it (`threshold_color`, `threshold_dash`, `threshold_width`) keep their names.

**Branch outcome keys.** Every figure that draws branch outcomes uses one encoding (`OUTCOME_COLORS` in `figures/palette.py`): kept is a filled mid-grey triangle, absorbed a filled black triangle, elder-protected a filled orange triangle (not drawn by any current figure; the band rule's outcomes are only kept and absorbed, `BAND_OUTCOMES`). A key sits inside its tree panel at the corner holding the least of the tree (`outcome_legend_corner`; ties go top-right, `outcome_legend_clearance` breaks a tie) and lists only the states present in the data.

| `bootstrap_global_stability` | peaks above the threshold mid-grey (`peak_color`), below it black (`absorbed_color`); no outcome colours | none |

## Bootstrap figures

The bootstrap stage (`just bootstrap-smoothed-tree`, depends on `just sequence-growth-rates`; settings `[bootstrap_smoothed_tree]` in `config/analysis.toml`; ADR 0008 (bootstrap smoothing), [design](bootstrap-smoothing-design.md)) bootstraps the nominal Candidate split tree, reads peak cores off the terminal co-occurrence of sequence pairs and absorbs every non-elder hill that no core meets or that loses to a higher peak inside a spanning core. The checkpoint is published to `output/checkpoints/bootstrap_smoothed_tree/` and exported byte for byte to `output/analysis/bootstrap_smoothed_tree/` (ADR 0013), the path the figures and tables read; it also keeps the flat-landscape decisions (`flat_cores.parquet`, `flat_hills.parquet`). Distances in `draw_stats` are taken between ordinary H0 persistence diagrams (birth = peak scalar, death = pairing-saddle scalar, the global maximum's pair closed at the global minimum). The global verdict in `summary.json` is a bootstrap confidence band (Fasy et al. 2014): `c` is the `band_quantile` quantile of the real draws' bottleneck distance, nominal points with persistence above `2c` (the bootstrapped persistence threshold) are significant, and `hills.parquet` carries each hill's `nominal_birth`, `nominal_death`, `nominal_persistence`, `clears_band` and `band_outcome` (kept or absorbed). The only comparison with the flat draws is `global_verdict.sanity_check`. The stage also builds the band-simplified tree (absorbs every `absorbed` hill in one call, fails closed unless the survivors equal the `clears_band` hills with unchanged persistence and are nested in the core-rule tree, and records `band_simplification` in `summary.json`). Tables `papkou2023_bootstrap_hills`, `_cores`, `_vertex_roles` and `_draw_stats` are written to `output/tables/` with the sidecar `.bootstrap-smoothed-tree-provenance.json`. The checkpoint's schema and the artefacts do not depend on chunking. `just bootstrap-band-quantile-scan` sweeps the band quantile over a grid (`grid_step` in `[bootstrap_band_quantile_scan]`, default 0.001), takes `c(q)` from the stage's `band_width` on the real draws, counts the nominal peaks with persistence strictly above `2c(q)`, and writes `scan.parquet` and `survival.parquet` (counts and thresholds only) to `output/analysis/bootstrap_band_quantile_scan/`; it never recomputes the bootstrap.

Chunked runs, checkpoint protection, mirrors and restoring are documented in ADR 0008 and 0013: draws are saved in chunks of `chunk_size` (default 250) per series (`observed`, `flat`) under `$FITNESSTREE_BOOTSTRAP_CHUNK_DIR`; SIGTERM, SIGUSR1 or SIGINT stops after the current chunk with exit code 124; `--fresh` moves chunks aside; the run is identified by its scientific fingerprint (result settings, the `noise_model` marker `pooled`, `candidate_functional_threshold`, input dataset digests; code digests ignored); after a run the stage publishes the checkpoint to `data/processed/bootstrap/<state>/checkpoint`; `load_cached_bootstrap_smoothed_tree` restores the processed checkpoint whose fingerprint matches `config/analysis.toml` when `output/` has no matching checkpoint, and never overwrites a processed one. Run one bootstrap per checkout at a time. `tests/data/bootstrap_golden/` holds tables the chunked path must reproduce exactly. Topographer is pinned in `pyproject.toml`.

## Analysis stages without a figure

**Ridges product.** `just ridges-product` publishes one `ridges` product per state with a functional class (published, reflected, published BY and reflected BY, nominal and band; Full has no threshold and is skipped), keyed on that state's tree keys and built from the saved leaves, tree and landscape products only. `ridges.parquet` is the KEM/TCL summary (`population`, `tree_state`, `ridge_name`, `summit_dna_sequence`, `summit_raw_fitness`, `common_saddle_dna_sequence`, `common_saddle_fitness`, `member_count`, `functional_count`, `functional_share` in percent of the selected graph's functional sequences). `members.parquet` lists every selected-graph sequence with `ridge_name` and `summit_dna_sequence` null for the common saddle, the trunk and unassigned sequences, and `functional_class` (BY: the saved classes; point-estimate: functional when raw fitness is at or above the threshold, never uncertain). The ridge rule is the glossary's: the superlevel component of the summit strictly above the common saddle, the saddle being the lowest common ancestor of the two nominated summits in that state's own tree. A state whose summit is not a tree maximum (for instance absorbed in a band tree) has empty tables and a sidecar reason. `summary.json` records, for a band state, the nominal saddle, whether it shifted and how many nominal ridge sequences the band ridge retained, and every terminal leaf by member count with the top three labelled.

**Candidate tree-edge contrasts.** `just candidate-tree-contrast` fits one direct BarSeqFit pair contrast per Candidate split-tree edge (from = lower endpoint, to = upper endpoint) and builds or reuses the checkpoint in `output/analysis/candidate_tree_contrast/`. It exports `papkou2023_candidate_tree_contrast_pairs` (the tested pair list) and `papkou2023_candidate_tree_contrast_edges` (contrast evidence, BH q-values over the `candidate_split_tree_edges` family, qualification at strict `q > alpha`, sign disagreement) as CSV and Parquet in `output/tables/`. No figure draws them. It needs the BarSeq export named by `PAPKOU2023_BARSEQ_EXPORT` and is not part of `just all`. See [candidate-tree-contrast-design.md](candidate-tree-contrast-design.md).

**Branch decomposition.** `papkou2023_branch_decomposition` is an exploratory analysis stage, not a figure: it has no `FigureSpec`, no figure identifier, no variants, no `[figures.*]` table and no PNG in `output/figures/`, and it is not part of `just all` or `just figures`. `just branch-decomposition` (`analysis/branch_decomposition.py`, a produce-or-load stage under ADR 0013 keyed on `[branch_decomposition]` of `config/analysis.toml`, the bootstrap checkpoint's fingerprint and artefact hashes, Topographer's installed sources and the code that builds the tree) lists every edge as one branch: `tree = "band"` (default) is the direct band-simplified tree and `"nominal"` the unsmoothed tree. A branch is one tree edge, the per-edge reading of Branch span and Branch vertex count in the glossary and of Topographer's `build_tree_metrics().branch_table`; it is not an elder-rule path. It reads the bootstrap checkpoint through `load_cached_bootstrap_smoothed_tree` and never draws, so the recipe does not depend on `bootstrap-smoothed-tree`; it needs `data/raw/` to rebuild the nominal tree and the Full graph, and the tree must match the checkpoint's hills.

The checkpoint `output/analysis/branch_decomposition/` holds `branches` (`.parquet` with a list column, `.csv` with `;`-joined members), one row per tree edge:
- `branch_id`, the sequence of the edge's upper endpoint (unique: a peak for a terminal branch, a saddle otherwise);
- `peak_sequence`, the elder peak whose elder path runs through the edge;
- `parent_branch_id`, the edge below (null when the edge ends at the root), and `is_terminal`;
- `horton_strahler_order`, Topographer's order of the edge on the smoothed tree;
- `branch_vertex_count` and `member_sequences`, the sequences on the edge after absorption;
- `edge_count`, the number of single-mutation adjacencies of the Full graph;
- `birth_fitness`, `death_fitness` and `branch_span`, the raw fitness at the two endpoints and their difference.

`members` (long form: `branch_id`, `dna_sequence`, `raw_fitness`, `horton_strahler_order`, …) lists every member. **Leading saddle band.** `just leading-saddle-band` (`python -m dubanevics2026topological.build leading-saddle-band`) is a produce-or-load stage on the Full graph (ADR 0013; `analysis/leading_saddle_band.py`, registered in `build/tables.py` as `build_leading_saddle_band_tables`), not part of `all` or `figures`. It reads the cached full-network component pairs (`load_cached_component_persistence`; the Full-graph split tree is not loaded), the Full-graph raw fitness and `fitness_diff`, and measures the band's connectivity on the Full graph (`Papkou2023Workflow(...).build_network()`). It computes ordinary H0 pair deaths only. Its fingerprint keys on the Published functional threshold, the Candidate threshold declaration (rule and digits), the functional-classification checkpoint that supplies the active `T`, the component checkpoint's fingerprint and artefact hashes, and the stage's code.

The four saddles, each with its DNA sequence identity (ties broken by the smaller sequence): the split-tree leading saddle (highest split saddle death) and trailing saddle `b_split` (lowest), and the join-tree leading saddle (lowest join saddle death) and trailing saddle `b_join` (highest). The split saddles are the deaths of the cached pairs of kind `relative`, the join saddles those of kind `ordinary`. `b_split` is `TopologicalNoiseBand.lowest_split_saddle_death` (both call `tree_saddles`). The stage checks `b_join` against `build_threshold_diagnostics(...)["join_tree_trailing_saddle"]` and fails closed on a difference.

The checkpoint is `output/checkpoints/leading_saddle_band/` (with `provenance.json`) and its files are exported to `output/tables/`, `summary.json` as `leading_saddle_band_summary.json`:
- `leading_saddle_band_landmarks` (`.csv`, `.parquet`, `.schema.json`): one row per landmark with `landmark`, `fitness`, `sequence`, `source`, `band_kind` and `median_inside_band`. Landmark keys: `global_minimum`, `split_trailing_saddle`, `join_trailing_saddle`, `median`, `split_leading_saddle`, `join_leading_saddle`, `published_functional_threshold`, `candidate_functional_threshold`. The minimum and the four saddles are vertices and carry a `sequence`; the thresholds do not; the median carries one only when exactly one vertex has raw fitness equal to it. Every saddle and the minimum must be a Full-graph sequence whose `raw_fitness` equals the pair scalar, or the stage raises.
- `leading_saddle_band_intervals`: the sequences between consecutive landmarks sorted by fitness, named `<lower landmark>__<upper landmark>`, with `interval_index`, `lower_fitness`, `upper_fitness`, `upper_closed`, `sequence_count` and `percentage` of all Full-graph sequences. Intervals are half-open `[lower, upper)` except the last, which is closed.
- `leading_saddle_band_entropy`: long table `population`, `position` (codon position 1 to 3), `entropy` (bits of the amino acid; null for an empty population) and `sequence_count`, for the `band`, the `split_trunk`, the `join_trunk` and every interval. Per-ridge entropy belongs to the Candidate graph and is not produced here.
- `summary.json`: every scalar (`<landmark>_fitness` and `_sequence`; `band_kind`, `band_lower_landmark`, `band_lower`, `band_upper`, `median_inside_band`; band and trunk counts and percentages; `<population>_entropy_sum`; `interval_order`, `interval_counts`, `interval_percentages`, `interval_entropy_sums`; `total_sequence_count`; the candidate threshold's `median_gap`, unrounded value, rule and digits; and the band-induced subgraph on the Full graph as an undirected simple graph without self-loops: `n_components`, `largest_component_size`, `largest_component_fraction`, `n_singletons`, `band_internal_edges`).

Definitions: the band population is the closed interval `[band_lower, band_upper]`; the split-tree trunk is every sequence with raw fitness at or below `b_split`; the join-tree trunk is every sequence at or above `b_join`. `band_kind` is `overlap` when `b_join <= b_split` (the band is then the intersection of the two trunks) and `gap` when `b_join > b_split` (the band lies in neither trunk apart from its closed endpoints). Band and trunks are therefore not a partition. The figure `full_tree_fitness_landmarks` is drawn from these tables.

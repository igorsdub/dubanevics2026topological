## Published functional threshold provenance

Papkou et al. (2023), supplementary methods pp. 14–15, reported the normal
component parameters μ = -0.721 and σ = 0.069. Their 0.999 quantile is
`qnorm(0.999, -0.721, 0.069)` = -0.507773970874421, displayed as -0.507774.
The Published point-estimate path applies the six-decimal value in
`config/analysis.toml`; it selects 18,029 non-WT variants (18,030 including WT)
in the reproduced input. The `papkou_original` BY snapshot instead preserves
the formula precision -0.5077739708744209 as its applied threshold, as required
for compatibility with the archived classification. The values differ by about
2.9e-8. BY Functional counts are classification counts, distinct from
point-estimate counts.

The BarSeqFit reproduction compared 261,332 non-WT input variants with maximum
absolute fitness delta 0. The investigation, including the port
acceptance gates, was recorded in a BarSeqFit development report that is not part
of the `barseqfit v0.2.0` release. This paper's BarSeqFit pin is tag `v0.2.0`
(0.2.0).

| Method | Threshold | Functional non-WT variants | Role |
| --- | ---: | ---: | --- |
| Published | -0.507774 | 18,029 | Paper's Published point-estimate path |
| R normalmixEM k=2, full-precision refit, seed 1 | -0.507313425918757 | 18,014 | Refit comparison |

The approved BarSeqFit gates are: **A**, the published-parameter path is exact;
**B**, k=2 is within 1 variant and 1e-4 in threshold of the R refit; **C**, k=3
is report only. The refit thresholds do not replace the Published threshold.
The real-data precision and count check runs on the cluster with
`scripts/validation/published_threshold.py`.

## Candidate functional threshold

The Candidate functional threshold is a computed quantity, not a typed value
(ADR `adr/2026-10-24-mixture-quantile-functional-classification.md`).
`config/analysis.toml` declares the Selection rule and the rounding digits:

```toml
[clamped]
published_functional_threshold = -0.507774
candidate_functional_threshold = { rule = "fdr_fixed_cutoff", decimals = 6, cutoff = "median_reflected", method = "by", q = 0.05, input_dir = "data/reference/fdr-classification-inputs_by-q0.05_gen3c790c3e_3c16ddf2", table_sha256 = "3c16ddf2…" }
```

The active publication rule (user lock 2026-11-12) is `fdr_fixed_cutoff` with the
median-reflected cutoff under Benjamini–Yekutieli at nominal `q = 0.05`. `T` and the
Functional class are read from the reviewed clean snapshot; see
the variant files of `config/variants/` and `threshold/fdr_selection.py`. The
`mixture_quantile` rule remains available as `config/variants/mixture_quantile.toml`
(ADR 2026-10-24): that path takes `T` from the `functional-classification` stage and
selects the Candidate graph by the Functional class. The inputs and both values for
any rule are written to `candidate_functional_threshold.json` in the clamped
comparison checkpoint. The declaration and upstream identities are part of every
stage fingerprint that reads them, so changing the rule invalidates the caches.

**What the counts count.** `functional_vertex_count` and `uncertain_vertex_count` are
over the whole classification, that is the Full graph (every classified sequence),
not the largest component the Candidate graph keeps. They are `null` under
`median_reflected`. `selected_component_functional_vertex_count` (also in the
prepared landscape's diagnostics) is the number of Functional vertices inside the
retained component; Table 1's "Number of functional sequences" of the Candidate
graph is this in-component count, taken as the Candidate graph's vertices in the
Functional class (the registry's `candidate_graph.functional_count`), with the
Non-functional class in `nonfunctional_count` and the Uncertain class in
`candidate_graph.uncertain_count`. Under `median_reflected` all of these count raw
fitness at or above `T`.

The `median_reflected` rule is the comparison rule (ADR
`adr/2026-10-23-median-reflected-candidate-functional-threshold.md`, superseded as the
active rule). It computes `T` from the Full-graph raw-fitness population
(`analysis/candidate_threshold.py`): `m` is the median, `g` the global minimum, the
Median gap is `h = m - g`, and `T = round(m + h, decimals)`. On the full graph
`m = -0.7139811714`, `g = -1.1748028867`, `h = 0.4608217153` and
`T = -0.253159` (unrounded -0.2531594561). Every vertex at or above it is functional
and the edge rule is `at_least_one_endpoint_raw_fitness_ge_threshold`. Under either
rule the record keeps `m`, `g` and `h` of the Full graph: they are the numbers of the
Topological noise band, which holds under any rule as a symmetry assumption.

The earlier saddle-based derivation `2b - m` (`b` the join-tree trailing saddle) and the
`proposed_death_boundary` setting are removed. The join-tree trailing saddle is
still reported, as a separate quantity, so the ordering `g < b < m < T` is visible.
The extended-positive pair (Topographer's label for the full-network sweep's global
pair) records the global scalar range and is not an ordinary death.
